## 4. 备份、恢复和迁移演练说明

备份读取 `workspace/lab.sqlite3`，使用 SQLite backup API 合并 WAL，连同 uploads/models/target_profiles/experiment_outputs/reports/samples 复制；当前没有服务密钥文件，安全测试另外验证了“存在密钥时能完整恢复”。生产原始记录与媒体文件未被改写。

恢复到 `artifacts/a01-v2/phase0/restored/` 后先校验完整性和所有旧表内容，再执行迁移两次。迁移后的恢复副本自然不再与迁移前 manifest 的数据库哈希相同；原始 `backup/` 保持不变，可重新验证和恢复。

旧记录含绝对路径，因此恢复副本未作为业务服务启动。引用审计将原 workspace 根目录映射到恢复副本进行只读核对，确认全部依赖产物存在。浏览器测试使用另外新建的工作区，不使用这个含旧绝对路径的恢复副本。

备份工具检测备份期间数据库/文件内容变化并拒绝生成成功 manifest；维护备份期间应暂停业务写入。它不宣称对任意持续并发写入提供跨数据库与媒体的原子快照。

本次执行的主要命令（项目根目录）：

```powershell
.venv\Scripts\python.exe -m pytest -q -ra --junitxml=artifacts/a01-v2/phase0/baseline/backend.xml
.venv\Scripts\python.exe -m pytest -q tests/test_workspace_backup.py --junitxml=artifacts/a01-v2/phase0/safety/tests.xml
.venv\Scripts\python.exe scripts/workspace_backup.py backup workspace artifacts/a01-v2/phase0/backup
.venv\Scripts\python.exe scripts/workspace_backup.py restore artifacts/a01-v2/phase0/backup artifacts/a01-v2/phase0/restored
.venv\Scripts\python.exe scripts/run_browser_baseline.py artifacts/a01-v2/phase0/browser
```

前端构建在 `frontend` 目录执行 `npm run build`。迁移演练通过 Python 调用 `migrate(restored / 'lab.sqlite3')` 两次，并将旧表哈希、引用审计和正式数据对照写入 JSON。

重复实验需使用新的备份/恢复/浏览器证据目录；工具不会覆盖现有结果。可以随时只读复核原始备份：

```powershell
.venv\Scripts\python.exe scripts/workspace_backup.py verify artifacts/a01-v2/phase0/backup
```
