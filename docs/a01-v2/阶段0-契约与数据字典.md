# A01 v2 阶段 0：冻结契约与数据字典

状态：按已批准开发计划冻结的实现基线；本文件中的新接口尚未实现。后续变更需记录理由和版本，不得悄悄改变评价语义。契约版本 `a01.v2.1`，指标版本 `target-presence.v1`，数据结构版本 `2`。

## 1. 已批准范围与界面流程

A01 只有“目标人物声纹识别实验室”和“分析与报告”两个一级卡片。实验室内部按输入→Discovery→试听/确认→Profile→测试集/标注→实验方案→运行→结果→归档展开。没有实时锁定、麦克风入口。

完整实验：同一目标人物、同一建档音频、固定测试集与标注版本，比较一或多个配置。Discovery 和建档是该 Run 的内部步骤，不是独立 Run。历史 E1/E2/E3 仅供历史查阅，禁止混进新实验比较。

所有结果即时持久化；“保存本次实验”设置归档状态，不重新计算。刷新可以恢复草稿和进度；更改已经提交的配置要创建新 Run/新尝试。用于后续正式验证的 Run 必须固定配置，并标明 `purpose=validation`，不扫描调参。

## 2. 状态机与一致性

### Run

`DRAFT → DISCOVERING → AWAITING_CONFIRMATION → READY → QUEUED → RUNNING → COMPLETED`

- `DISCOVERING`：正在执行一个或多个 Discovery Job。全部成功后进入等待确认。
- `AWAITING_CONFIRMATION`：人工确认未齐全；不是失败，也不计完整实验完成。
- `READY`：所有路线已确认，测试集文件级标注齐全，模型与时长候选有效，配置可提交。
- 执行期任一必需 Job 失败：`FAILED`，保留成功的中间证据，未执行候选 `BLOCKED`。
- 用户取消：先 `CANCELLING`，确认进程结束后 `CANCELLED`。终态不能被晚到的 Worker 成功消息覆盖。
- 服务重启：进行中 Job 标记失败，原因 `SERVICE_RESTARTED`；不自动重放任务，不声称已恢复完成。
- `archived_at` 为归档字段，不与运行状态混为一谈；`evaluation_status` 独立表明文件级可评、时间段级可评或证据不足。
- 只有草稿/等待确认阶段允许配置变化，使用 `revision` 乐观并发校验；失配返回 409。变化须使依赖的确认/Profile/得分失效。
- 提交携带 `idempotency_key`；同 Run、同 key、同 payload 返回原提交结果，同 key 不同 payload 返回 409。

### Job / Candidate

- Job：`QUEUED/RUNNING/SUCCEEDED/FAILED/CANCELLING/CANCELLED/BLOCKED`；API 主进程是业务数据库唯一写入者，Worker 返回有版本的产物，不改业务状态。
- Candidate：`PENDING/RUNNING/COMPLETED/FAILED/BLOCKED/CANCELLED`，每个阈值候选引用相同的不可变 score_set。
- 所有状态保留起止时间、原因码、可读错误及尝试关联；Job 的 SUCCEEDED 必须同时满足退出码正常、协议合法和产物完整。

### Worker 协议（阶段 1 实现）

输入包含 `protocol_version/job_id/operation/model_snapshot/input_artifacts/parameters/output_directory`；不接受任意 shell 语句。操作限定 `discovery/profile/recognition/model_test`。按实际需要可增加受控下载后测试入口，不接收任意 Python 代码。

进度与最终结果使用带版本的 JSON 消息或文件，诊断日志走独立 stderr。父进程校验 job_id、路径范围、有限数字、向量维数、结果哈希和退出码；产物临时写入完成后原子改名。取消先请求结束，超时再终止对应进程树。

内存字段采用 `peak_memory_bytes`、`memory_measurement`、`memory_sampling_interval_ms`；采样最大值与 OS 峰值不得混称。不能采集时使用 null 和原因，禁止填 0。

## 3. 数据字典

沿用当前 `{id, data(JSON)}` 存储风格；新增表通过显式迁移创建，必要引用字段建立 JSON 表达式索引。后端 Pydantic schema 负责新记录完整校验；跨记录一致性由服务层在事务内检查。以下为必需业务字段，时间均 UTC ISO-8601，时长/区间为毫秒，得分为有限浮点。

|---|---|
| target_people | id、display_name、created_at、owner；姓名变动不改变身份 ID |
| experiment_runs（扩展） | id、schema_version、scene=A01、kind=A01_OFFLINE、purpose、status、revision、target_person_id、input_config、input_snapshots、model_snapshots、ground_truth_snapshots、evaluation_protocol、code_fingerprint、created/started/finished/archived_at、owner、error、retry_of_run_id |
| model_jobs | id、run_id（模型自检可为空）、operation、model_snapshot、status、pid、started_at、finished_at、exit_code、error_code、error、peak_memory_bytes、memory_measurement、logs、artifact_manifest、attempt |
| discovery_results | id、run_id、job_id、audio_id、route_id、route_parameters、segments、speakers、preview_artifacts、algorithm_version |
| speaker_confirmations | id、run_id、discovery_result_id、target_person_id、speaker_ids、excluded_segment_ids、revision、reviewer、created_at |
| target_profiles（扩展） | id、schema_version、person_name快照、target_person_id、source_audio_id、source_discovery_id、confirmation_id、source_speaker_ids、used_segments、speaker_model_snapshot、requested_duration_ms、actual_duration_ms、embedding_path、embedding_sha256、embedding_dimension、aggregation_version、created_at |

| ground_truth_segments | id、ground_truth_file_id、start_ms、end_ms；标注保存时规范化为并集 |

新 Profile API 默认不返回向量；内部证据保存向量文件与哈希，报告不向外部 LLM 发送向量。模型多能力字段 `capabilities[]` 兼容旧 `capability`，由后续迁移/读适配处理，不在阶段 0 改写注册配置。

### 输入与可比性指纹

输入指纹包括原始和标准化音频哈希、模型权重哈希、实际设备、VAD/切窗/预处理版本。比较组包括 target_person_id、测试集音频哈希、有序标注快照版本、评价协议和用途。不同组允许综合描述，不混排名。

缓存 key 使用规范化 JSON 的 SHA256，并保存组成字段供审计：Discovery 使用建档音频+路线/权重/参数；embedding 使用音频+预处理/窗口+模型权重；Profile 使用选段+聚合规则+目标模型；score 使用 profile 向量哈希+测试 embedding。阈值与标注变化均不要求重新推理。

**错误统一形状**：`{"error":{"code":"PROFILE_AUDIO_TOO_SHORT","message":"可用目标语音不足60秒","details":{"requested_ms":60000,"available_ms":42000},"run_id":"...","job_id":null}}`。

## 5. 评价与推荐冻结规则

以批准计划第三节为准，下列内容用于实现与验收断言：

- 文件级：任意有效片段 score≥threshold 则判有目标；以文件数形成 TP/FP/FN/TN。
- 时间段级：只纳入完整目标标注的文件，以完整时间轴毫秒数形成 TP/FP/FN/TN；按区间并集计算，VAD 漏检仍计 FN，边界半开，默认无容忍区间。
- Precision=TP/(TP+FP)，Recall=TP/(TP+FN)，F1=2TP/(2TP+FP+FN)，False Accept=FP/(FP+TN)，Miss=FN/(TP+FN)。零分母输出 null 与原因，绝不补成满分。
- 时间段 False Accept 分母包括静音，必须同时展示 FP 秒数与分母；仅目标标注无法声称这是纯“其它说话人语音误认率”。
- 跨文件先汇总混淆量再求指标；同时保留逐文件值。不同指标层级不混排名。
- 默认阈值 0.60～0.90、步长 0.02，用整数步生成避免浮点重复。至少 16 阈值和 1 阈值两种执行的模型调用次数应完全相同。
- 排名 F1 降序→False Accept 升序→时长升序→candidate_id 稳定排序；null 指标不能参与该项最佳推荐。
- 稳定区间为推荐点所在的连续合格已测点集合：F1 降幅≤0.01，False Accept 升幅≤0.005；至少 3 点，不跨过失败点，不外推扫描边界，非置信区间。
- 临界样本 |score−threshold|≤0.02；它是复核对象，不自动算错误。
- 阈值优化仅作为调参结果。当前没有业务误认上限或最低召回要求，默认只形成“候选基线待确认”，不自动通过技术基线。
- 只有一个路线/模型的真实结果时，LLM 必须说未比较；九项分析中无法确定的项说明证据缺口。

## 6. 迁移和恢复约定

阶段 0 仅在恢复副本执行 `scripts/a01_schema.py`。脚本开启事务，接受旧 `user_version=0`，添加 v2 表和查询索引、迁移记录，再写入版本 2；重复执行不变化，未来未知版本或不完整结构拒绝。旧表、旧 JSON、旧状态与模型设置不改写。

后续运行时接入迁移必须等阶段验收；新记录显式标记 schema_version，读取旧记录按旧界面适配。修改表或语义增加新迁移版本，不修改已应用迁移含义。没有自动破坏性 down migration。

恢复采用新目录完整副本或在最终发布维护窗口将原目录保全后恢复原路径。旧记录包含绝对路径，当前备份工具保持原字节，不把搬迁副本启动为服务；阶段 0 通过源根目录映射审计恢复副本引用。真正搬迁部署需要独立路径重定位方案，不能让副本误写原工作区。

备份使用 SQLite backup API 合并 WAL；复制上传、模型、声纹、实验产物、报告、样本、存在时的服务密钥。日志不属于数据库恢复包，测试日志另外保留。前后校验全表逻辑哈希与证据哈希，发现期间写入即判失败；只有成功生成 manifest 并验证的包可恢复。该工具是维护期工具，不替代持续写入中的分布式事务快照。
